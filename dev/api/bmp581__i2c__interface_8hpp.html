Detailed Description

The I2C port of the BMP581 driver: the CRTP base, the I2cPort concept, the bus requirements and the register framing.

The driver never calls an SDK. On I2C it calls hooks on a class you derive from bmp581::I2cInterface<Self>:

Hook Contract
bool EnsureInitialized() noexcept Bring the bus up on the first call; true at once afterwards
bool Write(uint8_t addr, const uint8_t* data, std::size_t len) noexcept START, addr + W, len bytes, STOP; false on a NACK or bus error
bool WriteRead(uint8_t addr, const uint8_t* tx, std::size_t tx_len, uint8_t* rx, std::size_t rx_len) noexcept START, addr + W, tx, repeated START (or STOP and START), addr + R, rx_len bytes, STOP
bool GetLastFailure(I2cFailure& failure) noexcept (optional) After Write() or WriteRead() returned false: why. true and failure set when the port knows

addr is the 7-bit address. The port moves raw bytes: the register address travels in the payload, and the port never retries or configures the chip. What the chip needs from the bus is below as constexpr values in bmp581::i2c; a port checks its settings against them with static_assert. DelayUs() and Log() are described in bmp581.hpp.

Section, table and figure numbers refer to the Bosch BMP581 datasheet, document BST-BMP581-DS004-13, revision 1.13.
