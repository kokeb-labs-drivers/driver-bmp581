Detailed Description

The SPI port of the BMP581 driver: the CRTP base, the SpiPort concept, the bus requirements and the register framing.

The driver never calls an SDK. On SPI it calls hooks on a class you derive from bmp581::SpiInterface<Self>:

Hook Contract
bool EnsureInitialized() noexcept Bring the bus up on the first call, CSB high before the first frame; true at once afterwards
bool Transfer(const uint8_t* tx, uint8_t* rx, std::size_t len) noexcept One full-duplex frame, CSB low for all len bytes; rx may be nullptr

Four-wire SPI only (section 6.2.2): the driver never sets DRIVE_CONFIG.spi3_en. The chip starts in I2C mode after a power-on or soft reset and changes to SPI on the first frame with at least 16 SCK edges, whose data is invalid (section 5.1); the driver sends that dummy read itself, in EnsureInitialized() and after each soft reset. The port moves raw bytes: it never retries and never interprets the frame. What the chip needs from the bus is below as constexpr values in bmp581::spi; a port checks its settings against them with static_assert.

Section, table and figure numbers refer to the Bosch BMP581 datasheet, document BST-BMP581-DS004-13, revision 1.13.
