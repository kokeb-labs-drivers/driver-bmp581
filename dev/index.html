BMP581 Driver¶

A C++20 driver for the Bosch BMP581 barometric pressure and temperature sensor, on I2C or SPI. It starts the chip from a soft reset, measures on request or continuously, reads the FIFO, and never returns a stuck line, a reset value or an out-of-range reading as a measurement, on any MCU.

Quickstart API guide Source on GitHub

The BMP581 is an absolute barometric pressure sensor that measures pressure from 30 kPa to 125 kPa and temperature, and linearises and compensates both on the chip (1 Basic Description, p. 2).

  • Vertical speed indication

Barometric pressure sensor BMP581 Bosch Sensortec
Function
Absolute pressure, 30 kPa to 125 kPa at 1/64 Pa per count; temperature, -40 °C to 85 °C at 1/65536 °C; compensated on the chip
Interface
I2C up to 1 MHz at 0x46 or 0x47 (SDO), or four-wire SPI up to 12 MHz, mode 0 or 3; I3C (not used here)
Modes
Standby and deep standby; forced (one measurement); normal at 0.125 Hz to 240 Hz; continuous
Data
Oversampling x1 to x128, an IIR filter, a 32-frame FIFO, interrupts for data ready, FIFO full and threshold, and pressure out of range
Supply
VDD 1.71 V to 3.6 V, VDDIO 1.08 V to 3.6 V; 1.3 µA at 1 Hz in low-power mode

Quick start¶

Wire the chip as above, write the port for your MCU (Porting), then:

#include "bmp581.hpp"

int read_pressure(MyPort& port, float& pascals, float& celsius) {
  bmp581::BMP581<MyPort> sensor(port, bmp581::ForcedPreset()); // no I/O yet

  if (auto r = sensor.EnsureInitialized(); !r) { // 1. soft reset, CHIP_ID, NVM ready, Config
    return static_cast<int>(r.error); //    NoDevice, Bus or DeviceIdMismatch: check wiring
  }
  const auto m = sensor.MeasureOnce(); // 2. one forced measurement, then standby
  if (!m) {
    return static_cast<int>(m.error); //    every failure is an Error, never a number
  }
  pascals = bmp581::PressurePa(m.value.pressure_raw);      // 3. 1/64 Pa, exact
  celsius = bmp581::TemperatureC(m.value.temperature_raw); //    1/65536 °C, exact
  return 0;
}

From docs/hardware.yml; kokeb-docs hardware --check confirms that every API name is in inc/bmp581.hpp, inc/bmp581_types.hpp and every register in inc/bmp581_registers.hpp.

The driver has no platform code. You give it a small class that brings the bus up and moves bytes; it does the rest: the soft reset and the post-power-up checks, the configuration written in standby and read back, the power modes, the data and FIFO reads, the conversion to pascals and degrees Celsius, and the reset check.

What you get¶

  • One object per chip, on either bus. BMP581<YourPort> takes a reference to an I2C or an SPI port and does no I/O until EnsureInitialized(). See API guide.
  • Values you can trust. One 12-byte read per measurement, checked for stuck and floating lines, the reset value and the measurement range before a value is returned; FIFO frames carry their own validity. See Contract.
  • Resets found, never written over. A brown-out mid-session is found by the next read or setter, confirmed by a second read, and reported as DeviceReset; nothing cached is written over the reset chip. See Contract.
  • Datasheet defaults. Config{} holds the chip's reset values with units in the field names, plus four presets; Validate() checks the ranges and the data rate table. See Configuration.
  • Zero-overhead portability. The port is a CRTP class checked by a concept: the bus hooks and a delay, plus optional failure and logging hooks found at compile time. See Porting.
  • No heap, no exceptions, no RTTI. The host tests build with -fno-exceptions -fno-rtti. See Contract.
  • Tested without hardware. Host tests and a fuzzer run the driver against a register model of the chip that measures, resets and fails on its own. See Testing and CI.
